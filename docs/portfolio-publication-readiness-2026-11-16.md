# Готовность Axyro к публикации в портфолио

Проверено 16 ноября 2026 года по коду и опубликованному кабинету. Это текущая
проверка ограниченного набора сценариев, а не подтверждение всех функций
из исторических отчётов о приёмке.

## Принятое оформление

Владелец выбрал второй вид кабинета (V4). Он открывается по обычному адресу
`https://axyro.tech/portfolio/control-center`. Варианты сравнения сохранены
как `?design=previous` и `?design=new`. Данные при смене оформления сохраняются.

## Что уже подтверждено

- Кабинет использует штатный API и отдельную базу PostgreSQL.
- В базе есть пять аккаунтов, пять кампаний и 30 дней ежедневных показателей.
- Ранее проверены сохранение статуса и заметки, повторное чтение, журнал и XLSX.
- При сегодняшнем чтении API аккаунтов, кампаний, истории, сводки и шести
  разделов отвечают; ошибок JavaScript при обходе разделов не обнаружено.
- Отдельная сессия портфолио ограничена путём `/portfolio/`; Google Ads в этой
  среде использует SIMULATION, реальные операции с рекламой здесь не проверялись.
- Репозиторий публичный. Основная ветка — `main`; текущая публикация кабинета
  и публичного входа находится в `feature/axyro-portfolio-public-entry`.
- Исходники и образ интерфейса до доработки сохранены для возврата.

## До публичного показа

1. **Готово: главная страница соединена с рабочим кабинетом.** По адресу
   `https://axyro.tech/` опубликован утверждённый лендинг. Кнопка «Открыть
   кабинет» выдаёт посетителю ограниченную серверную сессию и открывает
   `/portfolio/control-center` без пароля и персональной ссылки. Старые
   `/demo/*` перенаправляются туда же. Закрытый вход владельца сохранён.

2. **Исправлено: согласованность отчёта.** Сводка использует ежедневные данные
   за выбранные даты и часовой пояс, как таблица и выгрузка. Снимок мониторинга
   не подставляется в чужой период. На отдельной PostgreSQL проверены шесть
   периодов в обоих режимах времени, XLSX, отсутствие данных и разные валюты.

3. **Подготовлен связанный набор.** Скрипт `scripts.portfolio_dataset` добавляет
   GEO/MCC, ежедневную статистику, регистрации и CPA, группы и объявления,
   модерацию, проблемы и уведомления, внутренний медиабюджет и отключённое
   правило DRY_RUN. Финансы показывают медиабюджет, без заявлений об активном
   Brocard. Повторная подготовка сохраняет правки посетителя. Остаётся пройти
   пользовательские сценарии из пункта 4 и определить обновление дат набора
   при длительной публичной работе; автоматического ежедневного обновления нет.

4. **Завершить приёмку сценариев.** Путь нового посетителя, повторный вход,
   выход, сохранение заметки и статуса на сервере, смена периода и XLSX
   проверены; ключевые страницы и вход проверены на телефоне. Остаются
   расширенные сценарии фильтров, сохранённых представлений, CSV и доступных
   операций кампаний. При публичном редактировании нужна политика очистки
   или восстановления общей базы после посетителей.

5. **Подготовить репозиторий для технического ревью.** README содержит ссылку
   на публичный кабинет и объяснение его границ; основное описание пока
   посвящено внутреннему сервису и перечисляет более широкий набор функций,
   чем доступен в портфолио. Нужны актуальное описание, архитектура,
   запуск, скриншоты, вклад автора и явные границы интеграций. После проверки
   подготовить изменения к основной ветке. До публикации новых материалов
   проверить текущие файлы и историю на секреты; из стандартных файлов
   `.env*` сейчас отслеживается только `.env.example`, полный аудит истории
   в этот проход не выполнялся.

## Порядок

Сводка, связанные данные и путь посетителя опубликованы. Далее завершить
приёмку оставшихся сценариев, определить восстановление общей базы и
оформить репозиторий для технического ревью. Для коммерческого запуска понадобится отдельная
приёмка реальных подключений и работы разных клиентов; этот список относится
к публикации проекта в портфолио.

## Результат обновления отчётности

На сервер опубликованы API `70f2268` и интерфейс `e3016c4`. Подготовлены
связанные записи в отдельной базе портфолио; исходная база скопирована до
обновления. Образы API и интерфейса до этого обновления сохранены с тегом
`before-reporting`.

Проверка по HTTPS подтвердила совпадение сводки со строками за today, yesterday,
3d, 7d, 30d в режимах ACCOUNT/MOSCOW, отсутствие чужих сумм в пустом диапазоне,
GEO/MCC и CPA, сохранение и повторное чтение заметки/статуса, прочтение и возврат
уведомления, XLSX и страницы статистики, модерации, финансов, уведомлений и
журнала на большом экране и телефоне. Административная смена статуса проблемы
остаётся закрыта оператору; соответствующие поля отключены в интерфейсе.

Автоматические проверки: 240 backend-тестов; отдельно 19 приёмочных проверок
отчётности на PostgreSQL; 56 frontend-тестов; TypeScript/production build и Ruff.
Реальные операции внешних Google Ads/Brocard в этот прогон не входили.
Публичный вход с главной закрыт следующим обновлением. Обновление/восстановление
общей базы после посетителей, расширенная приёмка кампаний и оформление
основной ветки остаются в работе.

## Результат подключения публичного входа

На сервер опубликована версия `612aee1`: отдельная сборка утверждённой главной
страницы и публичный вход в кабинет на серверной базе. Следующим обновлением
владелец выбрал V4 основным, прежний вид сохранён для сравнения. Подробности доступа, размещения и
возврата описаны в [portfolio-public-entry.md](portfolio-public-entry.md).

Перед публикацией сохранены копия базы, прежние образы API/frontend и
конфигурация шлюза. Исходная главная сохранена в
`~/axyro-portfolio/Caddyfile.before-public-entry.20261116T190451Z`.
Рабочие контейнеры владельца не пересобирались.

Публичное пространство использует подготовленные вымышленные записи и
сохраняет изменения на сервере. Интерфейс сообщает, что данные общие.
Реальные подключения и ключи не допускаются в публичной среде; проверка
повторяется при каждом запросе публичной сессии. Внешняя синхронизация закрыта,
кнопки обновления повторно читают данные из базы.

Автоматические проверки: 240 backend-тестов; отдельно 34 проверки публичного
входа и отчётности на PostgreSQL; 57 frontend-тестов; после последних изменений
интерфейса — 20 целевых проверок; TypeScript и сборки `/portfolio/` и `/showcase/`.
Ruff, проверки Compose и Caddy прошли. Доступность изображений, шрифтов и
инициализации темы подтверждена на пересозданных контейнерах.

Финальный прогон по HTTPS на этой версии прошёл в чистых браузерных сессиях:
главная, вход по кнопке без пароля, сохранение и возврат правок, повторное
использование сессии, выход без автоматического повторного входа, старые
ссылки, правовые страницы и мобильный экран. Проверены отсутствие ошибок
JavaScript/CSP и недоступных ресурсов, отдельная защищённая cookie, отсутствие
доступа к закрытому API владельца и запрет внешней синхронизации.
