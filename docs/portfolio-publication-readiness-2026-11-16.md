# Готовность Axyro к публикации в портфолио

Проверено 16 ноября 2026 года по коду и опубликованному кабинету. Это текущая
проверка ограниченного набора сценариев, а не подтверждение всех функций
из исторических отчётов о приёмке.

## Принятое оформление

Владелец выбрал прежний вид кабинета. Он открывается по обычному адресу
`https://axyro.tech/portfolio/control-center`. Варианты сравнения сохранены
как `?design=previous` и `?design=new`. Данные при смене оформления сохраняются.

## Что уже подтверждено

- Кабинет использует штатный API и отдельную базу PostgreSQL.
- В базе есть пять аккаунтов, пять кампаний и 30 дней ежедневных показателей.
- Ранее проверены сохранение статуса и заметки, повторное чтение, журнал и XLSX.
- При сегодняшнем чтении API аккаунтов, кампаний, истории, сводки и шести
  разделов отвечают; ошибок JavaScript при обходе разделов не обнаружено.
- Отдельная сессия портфолио ограничена путём `/portfolio/`; Google Ads в этой
  среде использует SIMULATION, реальные операции с рекламой здесь не проверялись.
- Репозиторий публичный. Основная ветка — `main`, опубликованные изменения
  кабинета пока находятся в `feature/axyro-portfolio-design-v4`.
- Исходники и образ интерфейса до доработки сохранены для возврата.

## До публичного показа

1. **Соединить главную страницу и рабочий кабинет.** При сегодняшнем обходе
   `https://axyro.tech/` отдаёт прежнюю публичную страницу с переходом на `/login`
   и формой логина/пароля. `/demo/control-center` также показывает вход.
   Рабочий `/portfolio/control-center` для нового посетителя требует
   персональную одноразовую ссылку. Нужно выбрать единый публичный адрес,
   разместить утверждённый лендинг и сделать доступный посетителю путь в
   изолированный кабинет. Существующий персональный просмотр уже работает.

2. **Исправить согласованность отчёта.** При `period=30d` расходы пяти строк
   составляют 64 720 USD, а сводка показывает 15 190 USD. `get_summary` в
   `backend/app/api/routes/control_center.py` читает сохранённые
   `AccountMonitoringState` и не принимает период; таблица рассчитывается по
   ежедневным данным. Нужно согласовать период и часовой пояс сводки, таблицы
   и выгрузки и проверить несколько диапазонов.

3. **Подготовить связанные сценарии работы.** На момент проверки API
   статистики, модерации, финансов, уведомлений, проблем и автоправил возвращают
   пустые списки. У аккаунтов не назначены GEO и MCC; нет настроенного расчёта
   CPA регистрации. Нужно заполнить подходящие таблицы согласованными данными
   вымышленной команды и показать настоящие операции сохранения и истории.
   Для необязательных интеграций следует определить объём публичного показа,
   чтобы посетитель понимал доступные действия. Выдавать подготовленные данные
   за актуальную выгрузку из Google нельзя.

4. **Пройти приёмку сценариев.** Проверить полный путь нового посетителя,
   смену периода и фильтров, сохранённые представления, изменение аккаунта,
   историю, CSV/XLSX и доступные операции кампаний; повторить ключевые действия
   на телефоне и при повторном входе. Текущая проверка открытия страниц не
   заменяет этот прогон. При публичном редактировании нужна политика очистки
   или восстановления общей базы после посетителей.

5. **Подготовить репозиторий для технического ревью.** README сейчас называет
   продукт закрытым внутренним сервисом и перечисляет более широкий набор
   функций, чем доступен в портфолио. Нужны актуальное описание, архитектура,
   запуск, скриншоты, вклад автора и явные границы интеграций. После проверки
   подготовить изменения к основной ветке. До публикации новых материалов
   проверить текущие файлы и историю на секреты; из стандартных файлов
   `.env*` сейчас отслеживается только `.env.example`, полный аудит истории
   в этот проход не выполнялся.

## Порядок

Сначала исправить сводку и подготовить связанные данные, затем собрать путь
посетителя и провести приёмку. Завершить описанием репозитория и публикацией
утверждённого результата. Для коммерческого запуска понадобится отдельная
приёмка реальных подключений и работы разных клиентов; этот список относится
к публикации проекта в портфолио.
