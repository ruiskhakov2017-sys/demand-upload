# Публичный вход в Axyro

Главная страница содержит кнопку «Открыть кабинет», ведущую на
`/portfolio/login?open=1`. Новый посетитель получает серверную сессию оператора
и переходит в центр контроля без пароля и персональной ссылки. Повторное
открытие использует текущую сессию. После выхода автоматический вход не
повторяется: посетитель должен снова нажать кнопку.

## Границы доступа

- Публичный вход работает только при `APP_ENV=portfolio` и явно включённом
  `PORTFOLIO_PUBLIC_ACCESS_ENABLED=true`; по умолчанию он отключён.
- База должна содержать подготовленный набор портфолио, только подключения
  SIMULATION и ни одного внешнего ключа. Эти условия проверяются при входе и
  при каждом авторизованном запросе публичной сессии.
- Посетитель получает только роль OPERATOR. Административные операции остаются
  закрыты; изменяющие запросы требуют CSRF.
- Cookie `axyro_portfolio_session` ограничена путём `/portfolio/`, имеет Secure,
  HttpOnly и SameSite=Lax. Она не авторизует запросы к рабочему `/api`.
- Публичные токены имеют отдельный префикс и хранятся в базе в виде хеша.
  Отключение флага сразу прекращает доступ по уже выданным публичным сессиям.
  Персональные одноразовые ссылки для приватного просмотра сохранены.
- Вход принимает только Origin публичного сайта. Создание новых сессий
  ограничено общим Redis-счётчиком: по умолчанию 30 в минуту. При отказе Redis
  новые публичные сессии не создаются; действующие сессии продолжают работать.
- Пространство общее: заметки, статусы и представления сохраняются на сервере
  и видны другим посетителям. Вход и кабинет сообщают об этом; политика
  конфиденциальности описывает серверное хранение. Автоматического обновления
  или сброса набора по расписанию в этой версии нет.
- Публичная кнопка обновления повторно читает данные из базы. Запуск внешней
  синхронизации в публичном маршруте закрыт на шлюзе; он не подменяется
  фиктивным сообщением о синхронизации Google Ads.

## Размещение

`showcase-frontend` — отдельная сборка утверждённой главной страницы с базой
ресурсов `/showcase/`. Основной frontend портфолио использует `/portfolio/`.
Публичный шлюз направляет `/`, `/privacy`, `/terms` и `/showcase/*` в новую
сборку. Закрытый `/login`, `/assets/*` и рабочий `/api/*` продолжают использовать
существующее приложение владельца. Старые ссылки `/demo/*` перенаправляются
в действующий кабинет.

Развёртывание выполняет `infrastructure/portfolio/publish-public-entry.sh`.
Архив `public-entry-<sha>.tar.gz` должен находиться в `~/axyro-portfolio/`;
скрипт принимает семизначный SHA. Он сохраняет конфигурацию публичного Caddy и
образы API/frontend, проверяет Compose и Caddy, собирает сервисы и проверяет
готовность перед переключением публичного маршрута.

После публикации при обновлениях передавайте все три файла окружения:
`.env.portfolio`, `.env.path`, `.env.public`. Последний содержит только флаг
публичного входа и хранится вне Git.

## Возврат

Для закрытия публичного входа задайте в `.env.public`
`PORTFOLIO_PUBLIC_ACCESS_ENABLED=false` и пересоздайте только API/worker с
этим файлом окружения. Выданные публичные сессии перестанут авторизовывать
запросы. Для возврата прежней главной страницы восстановите сохранённый
`Caddyfile.before-public-entry.<timestamp>` и выполните `caddy reload` после
проверки конфигурации. Базу данных для возврата маршрутов восстанавливать
не нужно.

Приёмочные тесты публичного входа: `backend/tests/test_portfolio_public_entry.py`.
Они используют только отдельную базу `axyro_portfolio_reporting_test`.
