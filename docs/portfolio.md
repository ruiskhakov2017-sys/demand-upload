# Рабочий кабинет Axyro для портфолио

Сборка запускает обычный кабинет V3, штатный API и отдельный PostgreSQL. При первом запуске миграции создают структуру базы, затем в неё загружается 30 дней показателей для пяти вымышленных рекламных аккаунтов. Код кабинета рассчитывает показатели, сохраняет изменения и формирует выгрузки через тот же API, что и рабочий Axyro.

Для приватного просмотра сохраните локальные значения в `.env.portfolio`. Используйте собственные случайные значения из латинских букв и цифр длиной не меньше 32 символов. Этот файл хранится вне Git.

```dotenv
PORTFOLIO_PASSWORD=
PORTFOLIO_DB_PASSWORD=
PORTFOLIO_SETUP_TOKEN=
PORTFOLIO_ENCRYPTION_KEY=
```

```sh
docker compose --env-file .env.portfolio -f docker-compose.portfolio.yml up --build -d
```

Откройте `http://localhost:19082/control-center` и войдите как `portfolio` с паролем `PORTFOLIO_PASSWORD`. Если сборка запущена на сервере, перенаправьте порт `19082` через SSH. Вариант привязан к локальному адресу для приватного просмотра.

1. Откройте North America. Измените рабочий статус и сохраните заметку.
2. Обновите страницу и проверьте изменения. Если аккаунт исчез из списка «Рабочие», переключите фильтр на «Все».
3. Откройте историю и найдите события по этому аккаунту. Выгрузите выбранный период в XLSX.

Google Ads в этой сборке использует режим симуляции. Для проверки реального запроса к Google можно отдельно настроить тестовую иерархию Google Ads. У таких аккаунтов нет показов и расходов, поэтому отчётность лучше проверять на подготовленном наборе данных.

## Связанные данные и отчётность

Инициализация также подготавливает GEO/MCC, группы и объявления, регистрации и
депозиты, CPA, результаты модерации, два уведомления и внутренний медиабюджет
команды. Все записи хранятся в PostgreSQL и читаются штатными API. Это данные
вымышленной команды; внешний Google Ads или Brocard при подготовке не вызывается.
Суммы внутреннего бюджета связаны с расходами аккаунтов; они не выдаются за
ответ платёжного провайдера.

На уже инициализированной базе один раз запустите из контейнера новой версии:

```sh
docker compose --env-file .env.portfolio -f docker-compose.portfolio.yml exec -T api python -m scripts.portfolio_dataset
```

Сначала сделайте резервную копию базы. Скрипт допускается только в окружении
`portfolio` с подключением Atlas в режиме `SIMULATION`. Подготовка выполняется
транзакционно и помечается в базе; повторный запуск не сбрасывает изменения
посетителей и не дублирует строки. Набор не обновляется автоматически каждый день.
Все пять вымышленных аккаунтов используют календарь `Europe/Moscow`, поэтому
режимы ACCOUNT и MOSCOW для этого набора имеют одинаковые границы дней.

Сводка и таблица считают ежедневные показатели за один выбранный период и
часовой пояс. Сохранённый снимок мониторинга используется только при точном
совпадении дат и режима времени; отсутствие данных не заменяется нулями или
расходами другой недели. Суммы разных валют не складываются.

Приёмочные тесты находятся в `backend/tests/test_portfolio_reporting.py`.
Они запускаются только с `APP_ENV=portfolio` и отдельной базой с именем
`axyro_portfolio_reporting_test`. Проверяются периоды, оба режима времени,
согласованность XLSX, пустой диапазон, разные валюты и сохранность правок при
повторной подготовке набора.

Чтобы выдать посетителю одноразовую ссылку на этот кабинет, выполните:

```sh
docker compose --env-file .env.portfolio -f docker-compose.portfolio.yml exec -T api python -m scripts.portfolio_link
```

Ссылка действует 24 часа. Посетитель нажимает «Открыть кабинет» и получает обычную сессию оператора. Каждый посетитель получает свою ссылку, все операторы работают с одной базой портфолио. Для публикации настройте обратный прокси с HTTPS и добавьте в `.env.portfolio`:

```dotenv
PORTFOLIO_PUBLIC_URL=https://axyro.tech/portfolio
PORTFOLIO_BASE_PATH=/portfolio/
PORTFOLIO_COOKIE_NAME=axyro_portfolio_session
PORTFOLIO_SECURE_COOKIE=true
PORTFOLIO_ALLOWED_HOSTS=["axyro.tech","localhost","127.0.0.1"]
```

На `rul1` добавьте к вызовам `docker compose` файл `-f infrastructure/portfolio/compose.ingress.yml`. Он подключает только прокси портфолио к сети `axyro-work_ingress`. Добавьте `infrastructure/portfolio/portfolio.caddy` в действующую конфигурацию Caddy, вставьте `import portfolio_path` в блок сайта `axyro.tech`, проверьте конфигурацию и перезагрузите её через `caddy reload`. Этот маршрут использует существующее HTTPS-подключение сайта и принимает только сессию портфолио. Продолжайте использовать этот блок при обновлении прокси.
