## MongoDB

В коде Axyro MongoDB не обнаружена.

Я понял MongoDB как документное хранилище: данные могут храниться не в таблицах и строках, а в документах с вложенными полями.

Пример идеи:

* PostgreSQL — таблицы, строки и связи между таблицами.
* MongoDB — документы, внутри которых могут быть вложенные данные.

На текущем этапе MongoDB изучалась как отдельная технология, а не как часть Axyro.

## Redis

Redis в Axyro используется как отдельный инфраструктурный сервис.

По коду проекта обнаружено:

* `backend/app/api/routes/health.py` — проверка доступности Redis через `redis.ping()`;
* `backend/app/core/config.py` — настройка `REDIS_URL`;
* `backend/app/jobs/celery_app.py` — Redis используется как `broker` и `backend` для Celery;
* в служебной документации проекта PostgreSQL указан как `source of truth`, а Redis — как `broker/cache`.

### Как я понимаю Redis

PostgreSQL хранит основное долговременное состояние приложения.

Redis используется для быстрой временной и служебной работы, например:

* очередь фоновых задач;
* передача задач между API и worker;
* временное состояние;
* кэш;
* данные с ограниченным сроком жизни.

## Worker и фоновые задачи

Фоновая задача — это задача, которая выполняется отдельно от первоначального запроса пользователя.

Пример:

1. API получает команду создать кампанию.
2. Задача передаётся через Redis.
3. Worker забирает задачу.
4. Worker выполняет работу.
5. Результат фиксируется отдельно.

Это позволяет API не ждать завершения всей долгой операции.

## Практика TTL

В локальном Redis был создан учебный ключ:

`homework:ttl:test`

Значение:

`hello`

TTL:

60 секунд.

После создания Redis подтвердил запись ответом `OK`.

При проверке TTL было получено:

`30`

После истечения времени команда `GET` вернула:

`(nil)`

Повторная проверка TTL вернула:

`-2`

Это подтверждает, что ключ автоматически удалился после окончания TTL.

## Что я понял про TTL

TTL — Time To Live, срок жизни ключа.

TTL позволяет хранить данные только ограниченное время. После истечения заданного срока Redis автоматически удаляет ключ.

Это удобно для временных данных, которые не должны храниться постоянно.
