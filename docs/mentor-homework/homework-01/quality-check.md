\# День 6 — Проверка качества и CI



\## Что изучалось



В День 6 я разобрал, как проект автоматически проверяет изменения перед добавлением их в основную ветку.



Главная идея:



CI (Continuous Integration) — это автоматический процесс проверки кода.



Он запускает проверки после изменений и показывает, есть ли проблемы.



\## CI в проекте Axyro



Файл:



.github/workflows/ci.yml



CI выполняет проверки backend, frontend и Docker Compose.



\## Backend проверки



Backend проходит следующие проверки:



\- установка зависимостей проекта;

\- проверка качества кода через ruff;

\- проверка типов через mypy;

\- проверка миграций Alembic;

\- запуск тестов через pytest.



\## Frontend проверки



Frontend проверяется через:



\- npm run typecheck;

\- npm test;

\- npm run build.



\## Что такое тест



Тест — это автоматическая проверка ожидаемого поведения системы.



Пример:



если компонент или функция получает определённые данные, результат должен соответствовать ожидаемому.



\## Практическая проверка



Был запущен тест:



backend/tests/test\_google\_ads\_adapter\_contract.py



Команда:



pytest tests/test\_google\_ads\_adapter\_contract.py -v



Первый запуск завершился ошибкой:



ModuleNotFoundError: No module named 'pydantic'



Причина:



тест был запущен через глобальный Python Windows, а не через окружение проекта.



После активации:



backend/.venv



тест был запущен повторно.



Результат:



3 passed



\## Что я понял



Для запуска проверок важно использовать правильное окружение проекта.



CI создаёт своё окружение и устанавливает необходимые зависимости автоматически.



Локально разработчик должен запускать проверки в окружении проекта.



Главная идея:



изменения должны проходить автоматические проверки до попадания в основную версию приложения.
